## ⚠️ 关键落地约束（必须先验证）

- **“与键序无关”的比较**：`extensions` 以外的字段按值比较，对象的键序不影响结果，数组的元素
  顺序影响结果；数值、字符串、布尔与 `null` 按 JSON 值比较。
- **只有全部同名文件都标合并时才合并**：任一方未标、内容不是 JSON 对象或 `extensions` 不是
  对象时，按同名文件逐字节比较，不一致即冲突。
- **同一命名空间**：两方都有同一命名空间时，内容按值相同才算一致，否则冲突。

## 任务

### 1. 合并（`src/build/merge.ts`，新文件）

- 输入：同一路径上各宿主的文件（宿主标识、内容、是否标合并），按宿主顺序；输出：合并后的
  内容，或冲突。逐字节相同的文件不解析，直接视为一致。

### 2. 产物计划（`src/build/outputs.ts`）

- `generatedFile` 与覆盖文件保留 `merge` 标记（覆盖生成文件时继承）；`mergeViews` 对标合并的
  路径调用 `merge.ts`，合并结果作为该路径的生成文件（`copyFrom` 为 `null`）；其余路径的处理
  不变（F-03-07）。

### 3. 文档

- 模块接口 §5、§8 与架构 §1 中“预留（F-03-07）”的说明改为已实现（M4-01 已改的部分不重复）。

### 不改的地方（红线）

- 现有夹具的期望产物不变，`merged-conflict` 的冲突信息不变。
- 未标合并的同名文件仍逐字节比较。
- 宿主模块不改，不为任何现有文件设置 `merge`。

### 测试

- 单元：`test/build/` 中以两个测试用宿主模块覆盖 TA-22 的各情况：字段相同而键序不同时合并
  成功；`extensions` 以外的字段不同、同一命名空间内容不同、只有一方标合并、内容不是 JSON 对象
  时冲突；覆盖文件替换带标记的生成文件后参与合并；`--check` 的差异与实际写出一致。
