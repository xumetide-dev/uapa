# 范围决策

本文记录功能清单的取舍：哪些进入哪个阶段、哪些延后或排除、哪些待确认。状态取值为
已定、待实测、待确认、延后、排除。

| 编号 | 主题 | 决定 | 理由 | 影响 | 状态 |
|---|---|---|---|---|---|
| SD-01 | 首批目标 | v0.1.0 只做五个目标；Cursor、Kiro、CodeBuddy、OpenCode、DSH 延后，每个目标按宿主模块的结构新增 | [ARCH-001](../architecture/ARCH-001-agent-plugin-build-tool.md) 冻结项；首个使用方只用到这五个目标 | 新增目标只新增宿主模块与能力数据，不改宿主无关模块的接口 | 已定 |
| SD-02 | 组件范围 | v0.1.0 只含 skills 与守卫 hooks；agents 与 MCP 放入 v0.2.0；commands 与 rules 暂不列入 | 首个使用方的试点插件只用 skills 与 hooks，其他插件另用 agents 与 MCP，均未使用 commands 与 rules | 01、05～08 模块的 v0.2.0 功能 | 已定 |
| SD-03 | 提示提交前检查 | 公共类型增加 `beforePrompt` 与能力 `promptGate`，列入 v0.1.0 | 首个使用方的试点插件在提示提交时做检查 | hooks 适配文档第 2、4、6 节需同步；各宿主的阻断能力待 TA-15 实测 | 待实测 |
| SD-04 | 执行后检查 | `afterTool` 放入 v0.2.0 | 试点插件不用；首个使用方的其他插件使用 | 02、04～07 模块的 v0.2.0 功能 | 已定 |
| SD-05 | 非守卫类 hooks | 会话开始时运行命令等非守卫类 hooks 不进入公共类型；是否允许源项目声明原样的命令 hooks 另行决定 | 首个使用方有插件在会话开始时运行命令；公共类型只描述守卫语义 | 迁移这类插件前需定稿 | 待确认 |
| SD-06 | 无数据目录宿主的停机计数 | Kimi Code 没有插件数据目录；拟把计数存于系统临时目录下以插件名与会话 id 命名的文件 | 停机门禁需要按会话计数，否则插件无法自设上限 | F-04-05；hooks 适配第 8 节需同步 | 待确认 |
| SD-07 | Codex 的 hooks 文件 | 提供目标选项 `hooksFile`；合并布局中与 Claude Code 共用 `hooks/hooks.json` 会因入口与命令不同而冲突，此时改用独立文件 | 每个目标生成自己的入口，不在运行时推断宿主 | F-06-02、F-06-03 | 已定 |
| SD-08 | 验收口径 | v0.1.0 以夹具逐字比对、宿主校验命令与行为测试为准，不以与既有手写文件逐字一致为准 | 增加 hooks 模块形态与按目标生成的入口后，产物文件集合必然与手写版本不同 | F-10-02、TA-12 | 已定 |
| SD-09 | 构建编排模块 | 新增 `src/build/`，承载逐目标构建、产物布局、合并与比对 | 架构文档的模块表中这些职责没有归属 | [架构](../architecture/architecture.md) §1、§2 已同步 | 已定 |
| SD-10 | 守卫配置的传递 | v0.1.0 只把 Claude Code 的 `userConfig` 透传到 manifest；守卫读取用户配置的统一接口不做 | 各宿主的用户配置机制未逐一核对 | 守卫需要可配置时再立项 | 延后 |
| SD-11 | 单文件可执行程序 | 不做 | ARCH-001 冻结项 | 无 | 排除 |
| SD-12 | VS Code 中的 Copilot | 不作为目标 | 只支持 8 个事件，见设计提案第 5 节 | 无 | 排除 |
| SD-13 | 默认产物目录 | 默认每个宿主一个目录，同一宿主的多个目标写入同一目录；合并布局指多个宿主共用一个目录 | Claude Code 两种形态互为兜底，必须在同一个插件包中（hooks 适配第 5 节）；设计提案第 9 节的布局按宿主分目录 | F-03-05、F-03-06、F-05-10；[架构](../architecture/architecture.md) §0 的产物布局已同步 | 已定 |
