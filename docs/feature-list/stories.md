# 角色与用户故事

本文列出 UAPA 涉及的角色、各角色的操作路径（用户故事）与按角色审计的结论。每条故事引用它依赖的
功能编号；宿主、打包器与包管理器是系统，不作为角色。预期结果中需要在宿主中观察的部分由宿主
实测验证（TA-11、TA-12、TA-15），不阻塞日常测试；自动化验证以所引用功能的验收标准与夹具为准。

## 角色

| 编号 | 角色 | 诉求 | 操作对象 | 边界 |
|---|---|---|---|---|
| P-01 | 插件作者 | 维护一份源项目，构建出各宿主可安装的插件包；守卫在每个目标上按宿主协议生效，或在构建时明确失败 | `uapa.config.ts`、守卫逻辑、`uapa build` | 不能让守卫静默失效：守卫 `requires` 中的能力目标不具备时该目标构建失败；其余能力缺失写入构建报告 |
| P-02 | 使用方仓库维护者 | 以固定版本引用 UAPA；门禁能发现生成文件与源项目不一致；升级时能评审差异 | `package.json` 依赖、门禁中的 `uapa build --check` | 只引用 tag，不引用分支；安装不运行 UAPA 的任何脚本 |
| P-03 | UAPA 维护者 | 宿主发版后更新能力数据；发布可复现的版本 | `src/capabilities/`、`pnpm check`、发布脚本 | 能力数据只写已核实的宿主行为并注明出处；检查未通过不发布 |
| P-04 | 插件最终用户 | 在宿主中安装插件后，危险操作被拦截并看到原因；守卫出错时不被静默放行 | 宿主的插件安装命令与日常使用 | 插件运行不依赖 UAPA 或任何 npm 包 |
